# Changelog

## 1.9.0

- Added a Panel Link (a small link icon in the title bar, `PanelLinkTitleItem` in the new `src/scenes/panelLinks.tsx`) alongside the existing Value Link on the Kubernetes home page's Clusters/Nodes/Namespaces/Workloads stat tiles, so the whole panel - not just the value area - carries a visible way to navigate to the linked page.
- Extended the Kubernetes home page's Efficiency tab demo data with real pod+container-level CPU/Memory usage rows (previously only node-level aggregates existed), and a `canary-rollout-aws` container with no matching resource-requests row - all 4 stat tiles, both "waste by namespace" bar gauges, and all 5 top-50 tables now show real data instead of "No data"/zero.
- The Overview tab's shared "Detail view" table now shows a specific, reassuring sentence per issue type (e.g. "No containers have been OOMKilled.") instead of the generic "No data" box when a selected issue has zero rows.
- Namespace Drilldown: the Logs and Events tabs now have a real Grafana Logs panel each, populated with a raw Elasticsearch log-line query (as opposed to the Overview tab's aggregated bar charts) and their own "Only warn/error" toggle; the Overview tab's Logs/Events bar charts gained a Panel Link to their respective tab.
- Namespace Drilldown Overview tab: the CPU/Memory requests quota cards now stretch to match the "Namespace information" info card's height instead of leaving a visible gap below them.
- Namespace Drilldown: built out the CPU, Memory, Network, and Storage tabs (previously "coming soon" placeholders), pasted verbatim from Grafana's own Kubernetes Monitoring app. CPU/Memory/Storage add a Pod filter picker (`createPodFilterVariable`) the rest of the page doesn't have; CPU/Memory each get 3 stat tiles, an "Overview: Usage" timeseries, "Distribution"/"Alignment" by-workload timeseries, and a combined-meter-cell Workloads table (Memory's also has a Limits column); Network gets Bandwidth/Saturation timeseries (plain + by-workload); Storage gets Ephemeral Volume Usage, PVC Storage Class/Volume Bytes/Volume inodes (plain + by-workload), PVC/PV Status, and Throughput/IOPS (plain + by-workload).
- Fixed three real demo-data gaps/bugs surfaced while building the above: (a) `debug-shell`'s workload identity disagreed between two metrics (`namespace_workload_pod:kube_pod_owner:relabel` said `"debug-shell"`, `kube_pod_owner`-derived rows said `"debug-shell-aws"`/`"-gce"`), which silently split its Workloads-page row in two *and* made the new Network tab's "by workload" queries hard-fail with Prometheus's "many-to-many matching not allowed" - fixed by aligning both to the pod's own name, which also happened to fix the pre-existing split-row issue; (b) `kube_pod_spec_volumes_persistentvolumeclaims_info` (the join key nearly every Storage tab PVC panel needs) didn't exist in the demo dataset at all; (c) `kube_persistentvolumeclaim_info` was missing the `volumename` label the new "PV Status" panel joins on. Also added pod+container-level CPU/Memory *requests* rows (`cluster:namespace:pod_cpu:active:...`/`cluster:namespace:pod_memory:active:...`) and per-workload network/filesystem-throughput demo rows the new tabs' `container!=""`/workload-attribution-joined queries needed - as a side effect, the Namespaces/Workloads pages' CPU/Mem Requests figures now reflect the real sum of individual container requests instead of a disconnected, inflated namespace-total placeholder.
- Namespace Drilldown Storage tab: moved the Throughput/Throughput by workload/IOPS/IOPS by workload legends to the bottom, and removed the Pod filter entirely (picker, scene variable, and every `pod=~"$pod"` matcher stripped from the underlying queries).
- Namespace Drilldown CPU/Memory tabs: replaced the Pod filter with a Workload filter, positioned above the stat panels row - filters the Distribution/Alignment timeseries via a `workload=~"$workload"` PromQL matcher and the Workloads table client-side via `filterByValue`. `createWorkloadFilterVariable` (previously scene-variable-only, for the Workloads list page) now accepts optional literal `clusterRegex`/`namespaceRegex` overrides for pages without one, same pattern `createNamespaceFilterVariable` already had.
- Fixed the CPU/Memory tabs' "Overview: Usage" panels not responding to the new Workload filter - the underlying queries had no workload dimension at all (a flat per-container sum), unlike Distribution/Alignment which already joined against `namespace_workload_pod:kube_pod_owner:relabel`. Added the same workload-attribution inner join to all 6 (limits/requests/usage × CPU/Memory) queries.
- Added a new top-level "All Jobs" page (`src/pages/Jobs/jobsPage.tsx`), reached from the Kubernetes nav alongside Clusters/Namespaces/Workloads/Nodes/Alerts: Datasource/Cluster/Namespace filters and two tabs, Cronjobs (Cronjob/Cluster/Namespace/Schedule/Last Succeeded/Last Schedule/Next Schedule/Status) and Jobs (Job/Controlled-by/Cluster/Namespace/Type/Start/End/Duration/Pods-Completion), each a single table built from `kube_cronjob_*`/`kube_job_*` metrics. Cluster/Namespace columns link to the Clusters/Namespaces Drilldown pages; Cronjobs' Status column is plain colored text (Active/Suspended); Jobs' Pods/Completion column is colored by job status (green=complete, orange=running, red=failed) with a "Job status" legend above the table, matching Grafana's own Kubernetes Monitoring app. Added the underlying demo metrics (`kube_cronjob_info` and friends for the existing `infra-check`/`user-check` CronJobs; `kube_job_owner`/`_status_start_time`/`_status_completion_time`/`_status_failed` for the existing `db-migrate` Job) - none of these existed in the demo dataset before, so every panel would have shown "No data".

## 1.8.0

- Added the Namespaces Drilldown page (`src/pages/Namespaces/namespacesPage.tsx`), reached by clicking a row on the Namespaces table - same structure as the Clusters Drilldown: namespace name + "namespace" badge title, "in cluster X" subtitle linking back to the Clusters Drilldown, and Overview/CPU/Memory/Network/Storage/Logs/Events tabs (only Overview has real content so far; the rest are scaffolded placeholders).
- Namespace Overview tab: an alerts-derived health banner and badge (namespaces have no synthetic health-probe CronJobs like clusters do, so "healthy/degraded" is derived from firing-alert severity instead), an info card (cluster link, workload count link, an EgressIP row not yet wired to a metric - none exists in this codebase/demo data), two CPU/Memory requests-quota cards modeled on the Resource Simulator's own summary cards (linking back to it, pre-filtered to this namespace), a "Namespace optimization" section with capacity/limits/requests/usage/allocation timeseries for CPU and Memory, a per-workload table (Workload/Type/CPU+Mem Usage+Requests+Limits/Pods, using the same combined meter cells as the Namespaces list table and the same ready/desired Pods cell as the Workloads page), and a "Logs / Events" section with two stacked bar charts (grouped by `log.level`/`event.type`) reading from a new dedicated Elasticsearch datasource variable that's regex-filtered to just the three log-management datasources these panels target (the org has many other Elasticsearch instances configured). Level/type colors are matched case-insensitively and cover common abbreviations (e.g. "Err"/"Error"/"ERROR" all resolve to the same color) since the underlying log source doesn't use consistent casing.
- Wired the EgressIP info-card row up to a real metric: `ovn_egressip_info`'s `egressip_assigned_0` label, matched by the fixed `monitoring-addons` namespace label plus an `environment_debeka_de` label carrying the actual namespace (the OVN-Kubernetes metric's own label scheme, not this app's usual `namespace` label). Required generalizing `InfoCard` to search every query's frame for a row's field instead of only the first one, since the egressip query is a separate query from the namespace info query and isn't joined/merged into the same frame.
- Folded the alerts badge into the health banner itself, immediately after the message text, instead of a separate badge floating above it. Not built on `<Alert>`'s own `action` slot: that slot sits in a sibling `Stack` next to a title `Box` that's `flex: 1, minWidth: '50%'`, which pushes the action to the far right with a big gap and no prop to change it - `NamespaceHealthBanner` now reimplements Alert's visual language (severity-tinted background/border/icon via the same `theme.colors[severity]` tokens Alert itself uses) as one flex row instead, and one query now covers both the banner's message and the button.
- Widened the namespace info card to half the row (was 40%, quota cards were 30% each) - quota cards now take a quarter each.
- Rebuilt the CPU/Memory requests-quota cards to reuse the Resource Simulator's own summary-card CSS classes directly (exported `getStyles` from `ResourceSimulatorObject.tsx`) instead of a similar-but-separately-styled card, so the two are pixel-identical and won't drift apart over time.
- Reworked the Logs/Events bar charts to actually merge same-meaning level/type spellings into one series each ("ERROR", "Error", "Err", "ERR" all become a single "ERROR" bar) instead of only color-matching them while leaving them as separate series/bars. Each canonical level (ALERT/ERROR/WARN/INFO/DEBUG/TRACE/Other for logs; Normal/Warning/Error/notice/Other for events) is now its own Elasticsearch query with a Lucene `OR` clause covering every known spelling variant, rather than one query with a `terms` aggregation grouped by the raw field value.
- Added an "Only warn/error" switch under the Logs/Events heading that drops the queries down to just the ERROR/WARN (or Error/Warning) canonical-level ones. Implemented as a direct `SceneQueryRunner.setState()` + `runQueries()` call from a small stateful React toggle rather than a Grafana template variable, since `CustomVariable`'s CSV-based option parser isn't a good fit for Lucene clauses full of colons and parentheses.
- Both bar charts' time-bucket interval now follows the timepicker (via `@grafana/data`'s `calculateInterval()`, the same helper Grafana panels use internally for `$__interval`) with a 1-minute floor - confirmed against a live instance that Elasticsearch date_histogram's own interval setting has no `">1m"`/minimum-floor syntax of its own (`"auto"`, `"$__interval"`, and concrete durations are accepted; `">1m"` and `"$__interval_ms"` both 400), so the floor has to be computed client-side instead.
- Renamed the demo stack's Elasticsearch datasource to one of the three names the new Logs/Events datasource variable filters on (it previously had no matching datasource in the demo environment at all), and extended the Elasticsearch seed script to index `logmgmt.kind`/`k8s.cluster.name`/`k8s.namespace.name`/`log.level`/`event.type`-shaped documents (explicitly mapped as `keyword`, not Elasticsearch's default analyzed `text`, since the panels' aggregations need exact-match fields) so the two panels have real demo data to render instead of "No data".
- Removed the per-bar value labels from the Logs/Events bar charts (`showValue: VisibilityMode.Never`) - with a stacked bar per time bucket and several series, the numbers were cluttering the chart rather than helping.
- Redesigned the Workloads page's CPU/Memory columns to match the Namespaces page's combined value+percent+bar cells (`usageTierCell`/`requestUsageCell` via `attachPercentField`), replacing the previous separate "value" + "value %" column pairs - same CPU-Usage-by-Requests / Mem-Usage-by-Limits coloring convention as everywhere else this cell style is used.
- Built out the Kubernetes home page's Alerts tab (previously a "coming soon" placeholder): a single timeseries panel, "Firing alerts by cluster" (`count by(cluster) (ALERTS{alertstate="firing", cluster=~".*"})`), with the same per-panel comparison control as every other timeseries panel in the app. Removed the now-unused `getComingSoonScene` helper along with it, since nothing else referenced it.
- Matched the Overview tab's 6 top stat tiles' color to Grafana's own Kubernetes Monitoring app - pixel-sampled directly from its docs screenshot (`k8s-overview-overvw-tab.png`), the reference renders a distinctly teal-leaning gradient (`#1CC4D7`), not Grafana's standard named "blue" hue the tiles used before.
- Matched the "Deployed container images" table to the same reference: the "Containers" bar-gauge column now uses `FieldColorModeId.ContinuousBlPu` (a blue-to-purple gradient scaled by value) instead of a flat fixed blue, has a fixed 160px width so "Image spec" fills the remaining space (previously both columns auto-sized evenly), and its footer reducer changed from `count` (number of image rows) to `sum` (total containers across all images) to actually show a meaningful "Total" figure - confirmed via the schema that a table footer is purely driven by a field's own `custom.footer.reducers` config with no separate panel-level toggle needed, though it didn't visibly render in this environment's Grafana build despite being configured correctly (worth re-checking against a real instance).

## 1.6.0

- Added reusable Badge-styled "value + percent + bar" and "icon + tier-colored value" table cell renderers (`requestUsageCell`, `usageTierCell` in `src/scenes/tableCells.tsx`), generalizing the sibling-field-value-attach transform the Workloads Pods column already used, for reuse on the Namespaces page.
- Fixed the Workloads table showing a stray "Value #desired_pods" column. The `hideFrom: { viz: true }` field override used to keep it out of the table while its value stayed readable for the Pods cell doesn't actually work on Grafana's Table panel: `custom.*` field overrides are silently dropped unless the active panel type registers that property in its own field-config registry, and Table doesn't register `hideFrom` even though its own rendering code checks for it (confirmed by swapping it for `overrideDisplayName` on the same field, which did take effect). The desired-pods value is now attached directly onto the ready-pods field's own config instead, so the raw field can be fully removed from the table rather than merely hidden.
- Deduplicated the `usageThresholds` config (previously redeclared identically in Clusters, Nodes, Namespaces, and Workloads) into a single export in `tableCells.tsx`, imported everywhere it's still used.
- Restyled the per-panel timeseries comparison control (Clusters Drilldown, Alerts) as a small colored Badge pill - matching the Resource Simulator's own quota-card badges - instead of a plain secondary button.
- Split the Resource Simulator's ~20 pure formatting helpers out of the 2400-line `ResourceSimulatorObject.tsx` into their own module (`resourceSimulatorFormatters.ts`), and replaced the plain "No workload rows" text alert with a proper empty state (icon, title, description).
- Redesigned the Namespaces table's CPU/Mem Requests and Mem Limits columns from separate "value" + "value %" column pairs into single combined cells (value, percent badge, proportional bar), matching the Resource Simulator's own used/requested meter style. CPU Usage and Mem Usage are now colored (icon + text) by their respective requests/limits ratio too - Mem Usage specifically by the *limits* ratio (the hard OOM-kill ceiling) rather than requests (only a scheduling reservation), since that's the more meaningful "about to hit the wall" signal.
- Added the per-namespace CPU/memory request and limit demo metrics the Namespaces page's queries actually read (`cluster:namespace:pod_cpu:active:...`, `cluster:namespace:pod_memory:active:...`) - they were missing entirely from the demo dataset, distinct from the similarly-named `namespace_cpu:.../namespace_memory:...` metrics the Clusters Drilldown Overview page reads, so the new combined CPU/Mem Requests and Limits cells above had nothing to show until now.

## 1.5.0

- Added a None/hour/day/week-before comparison picker to every timeseries panel on the Clusters Drilldown (CPU/Memory/Network/Storage/Overview tabs) and Alerts pages. It's a header action on each panel individually, not a single page-wide control - each panel toggles its own comparison independently. Rendered as a small ghost-style button (styled to match Grafana Play's own "Predict CPU usage" panel-header button) that opens a compact dropdown menu, rather than the framework's default full toolbar control. Table-only pages (Clusters, Namespaces, Workloads, Nodes) don't get it, since there's no timeseries to compare. New timeseries panels added to the Drilldown/Alerts pages pick it up automatically via `PanelTimeRangeCompare` (`src/scenes/panelTimeRangeCompare.tsx`).
- All pages' time pickers now default to the browser's local timezone instead of UTC.
- Added a Workload filter to the Workloads page, alongside the existing Cluster/Namespace filters. Row-filters the table client-side by the `workload` field, since that field only exists after the queries' own `label_replace` calls and can't be filtered with a PromQL selector the way cluster/namespace are. Its dropdown is sourced from the same expression the table itself uses to derive "workload" - the previous source (`kube_pod_owner{owner_name=...}`) only carries that label for ownerless pods, so it came back empty for every Deployment/DaemonSet/StatefulSet/Job. Sent as a single-line, comment-stripped query wrapped in `query_result(...)`: Grafana's `query_result(...)` wrapper-detection doesn't span newlines, so the original multi-line formatted expression fell through to being sent as a raw `match[]` series selector instead (which only accepts plain selectors, not aggregations/`label_replace`/`OR`), producing "invalid parameter \"match[]\": ... unexpected \"(\"".
